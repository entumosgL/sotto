# Sotto

Невидимый ИИ-суфлёр для собеседований под **Linux / Hyprland** и **Windows 11**, работающий на **твоих ключах и твоих агентах**.
Слушает разговор, подсказывает ответы в окне, которое не попадает в демонстрацию экрана, записывает
экран и звонки, ищет по ним по смыслу, тренирует к собеседованиям голосом и помогает с откликами на вакансии.

Никаких подписок и серверов: всё работает у тебя на машине. Платишь только провайдеру моделей за то,
что реально потратил (обычно **5–20 ₽ за час собеседования**).

Система отличается только «железной» частью, всё остальное одинаково:

| | Linux | Windows 11 |
|---|---|---|
| звук | PipeWire (`pw-record`), монитор выхода = голос собеседника | WASAPI (`soundcard`), loopback выхода = голос собеседника |
| невидимость оверлея | правило Hyprland `no_screen_share` | `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` |
| хоткеи | `hl.bind` в Hyprland (`SUPER + A`) | `RegisterHotKey` (`CTRL + ALT + A`) |
| скриншоты | grim / slurp | mss + Qt-выделение области |
| запись экрана | wf-recorder (VAAPI) | ffmpeg + ddagrab (NVENC / QSV / AMF / x265) |
| звонок определяется по | потокам микрофона в `pw-dump` | ConsentStore в реестре Windows |

## Что умеет

| | |
|---|---|
| **Подсказки в реальном времени** | По умолчанию **сами**: собеседник задал вопрос — в оверлее короткая подсказка (до трёх предложений, первые слова через ~2 с после конца вопроса), на «угу» суфлёр молчит. Можно «только по хоткею» и «короткий + подробный». Русский и английский, в том числе вперемешку. |
| **Ответ по экрану** | Снимок экрана или выделенной области + название активного окна + разговор → решение задачи, код, ответ на тест. Модель сначала пишет одной строкой, что видит, чтобы не путать онлайн-редактор без подсветки с багом. |
| **Легенда** | Модель сама решает, стоит ли дополнить опыт, которого нет в резюме. Всё придуманное подсвечивается в оверлее и сохраняется **за компанией**: на следующем этапе с ней суфлёр не противоречит себе, а в другие компании не переносит. Процесс закрыт (отказ, отказался, отменено) — легенда компании удаляется сама. На тренировках легенды нет: каждая — с чистого листа. |
| **Собеседования** | План: вставь приглашение — дата, ссылка и этап заполнятся сами; агент составит бриф по вакансии. Звонок в окне собеседования привязывается к нему сам (бриф и компания для суфлёра), за 15 минут — напоминание. Исходы этапов и воронка. |
| **Разбор отказов** | Отказали — агент читает расшифровки всех звонков с компанией вместе с подсказками суфлёра: главные причины с цитатами, где подвели подсказки, как надо было ответить. Слабые темы уходят в тренер. Общий разбор ищет повторяющиеся причины по всем отказам. |
| **Кто говорит** | Микрофон — «я», звук системы — собеседники. Несколько собеседников различаются по голосу. Имена подтягиваются из представлений («меня зовут Анна, я тимлид»), можно переименовать вручную. |
| **Невидимость** | Окно оверлея помечено в Hyprland как `no_screen_share`. Плюс режим **«сцена»**: виртуальный монитор, который ты показываешь в звонке. |
| **Запись** | Экран пишется всегда (2 кадра/с вне звонка, 5 в звонке, аппаратный HEVC, около 100–150 МБ/час), звук — отдельными дорожками «я» и «собеседники». Начало и конец звонка определяются сами. Хранится, пока не удалишь. |
| **Семантический поиск** | По названиям, описаниям и репликам всех звонков: «где спрашивали про Kafka», «HR из финтеха». RU и EN в одном пространстве, считается локально. |
| **Итоги звонка** | Семантическое название, краткое описание, вопросы и темы — делает твой CLI-агент после звонка. |
| **Тренеры (голосом)** | **Знания**: пробное собеседование или разбор темы с наставником. **Английский**: собеседование или разговорная практика с разбором ошибок. Темы подбираются сами: из ближайших собеседований, вопросов с реальных звонков, разборов отказов и вакансий. Интервальное повторение. |
| **Тестовый интервьюер** | `sotto sim` озвучивает сценарий собеседования, проверяет суфлёра (распознавание, имена, авто-режим, ключевые слова, задержки) и учит хоткеям. |
| **Вакансии** | Telegram-каналы, LinkedIn Jobs **и посты «ищем / hiring»**. Агент разбирает, оценивает соответствие и пополняет поисковые запросы. Вакансии группируются в **кластеры**: одно резюме и одно письмо на кластер, правки под конкретную вакансию — по желанию. |
| **Отклики** | Только по нажатию кнопки. Telegram (тем, кто написал «пишите @…»), почта, LinkedIn (откроет страницу и скопирует текст, отправляешь сам). Лимиты против бана и спама. |

Фоновые задачи (итоги звонков, промпты, тренеры, резюме, разбор вакансий) работают **через твои CLI-агенты**:
`claude`, `codex`, `opencode`, `kimi`, `grok`, `agy`. Ключ модели (OpenRouter или DeepSeek) тратится только на подсказки в реальном
времени. Упёрся агент в лимит — задача уходит следующему.

## Установка

Нужны Hyprland 0.55+ (Lua-конфиг) и PipeWire.

```bash
# попробовать
nix run github:<user>/sotto -- setup
nix run github:<user>/sotto -- run
```

**home-manager** (рекомендуется — демон стартует вместе с сессией):

```nix
# flake.nix: inputs.sotto.url = "github:<user>/sotto";
imports = [ inputs.sotto.homeManagerModules.default ];
services.sotto.enable = true;
services.sotto.cuda = true;   # NVIDIA: локальное распознавание речи на видеокарте (~0.5 с вместо ~7–18 с)
```

Без Nix: `pip install .` плюс системные `pipewire`, `ffmpeg`, `wf-recorder`, `grim`, `slurp`, `wl-clipboard`, `wl-mirror`.

### Windows 11

Нужны **Windows 11** (или Windows 10 2004+ — там появилось исключение окна из захвата экрана),
**Python 3.12+** (проверено на 3.14) и **ffmpeg**. Права администратора не нужны.

```powershell
# в PowerShell, из папки проекта
powershell -ExecutionPolicy Bypass -File .\install.ps1        # .venv + зависимости + автозапуск по желанию
# ffmpeg, если его нет:  winget install --id Gyan.FFmpeg -e   (потом открыть новое окно терминала)
```

Без установщика — вручную:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install .
.\.venv\Scripts\sotto setup     # провайдер и ключ (OpenRouter / DeepSeek / свой сервер), модели, профиль
.\.venv\Scripts\sotto run       # суфлёр + панель http://127.0.0.1:8765
.\sotto.cmd run                 # то же, без прописывания путей
```

Автозапуск при входе в систему (реестр `HKCU\…\Run`, без консольного окна):
`sotto autostart on` — выключить: `sotto autostart off`.

Что стоит знать про Windows:

* **Звук берётся прямо из WASAPI**: микрофон — это «я», звук системы (loopback выхода) — «собеседники».
  Устройства выбираются в панели → **Настройки → Звук**, менять их можно и в `[audio]` (`mic`, `system`).
* **Оверлей не попадает в демонстрацию экрана** через `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`:
  Zoom, Meet, Teams, Telegram и OBS его не видят. На старых сборках Windows вместо исключения работает
  затемнение (`WDA_MONITOR`): собеседник увидит чёрный прямоугольник на месте окна.
* **Хоткеи по умолчанию с CTRL + ALT** (см. ниже): `SUPER + A`, `SUPER + X` и `SUPER + H` заняты самой
  Windows 11 — система не отдаёт их программам.
* **Локальное распознавание** идёт на видеокарте NVIDIA (CUDA в `ctranslate2`), без видеокарты — на процессоре.
  Первый запуск скачивает модель (у `large-v3-turbo` ~1.5 ГБ) в фоне.
* **Виртуального монитора «сцена» в Windows нет** (нужен отдельный драйвер): в звонке показывай окно,
  а не весь экран, или подключи второй монитор. `sotto stage on` в Windows так и скажет.
* Эксперимент «переводчик звонка» требует виртуальных устройств PipeWire и в Windows не работает.

### Первый запуск

```bash
sotto setup          # провайдер и ключ (OpenRouter / DeepSeek / свой сервер), модели, профиль
sotto                # сайт http://127.0.0.1:8765, на нём кнопка «Запустить суфлёр»
sotto run            # то же, но голосовой суфлёр (звук, оверлей, хоткеи) запускается сразу
sotto sim tutorial   # 5 минут: тренировочное собеседование голосом, суфлёр подсказывает
sotto bench --apply  # замерить модели на твоём ключе и выбрать самые быстрые и дешёвые
```

Дальше всё через панель **http://127.0.0.1:8765**: профиль, собеседования, легенда, звонки и поиск, тренеры,
вакансии, резюме, промпты, настройки.

Суфлёр живёт в процессе `sotto`, а не во вкладке: закрыл сайт — подсказки и запись продолжают работать,
Ctrl+C в терминале останавливает всё.

**Текстом** (`/chat`) — проверка подсказок без звука: пишешь вопросы за собеседника сам или отвечаешь
интервьюеру-тренеру (тот же, что в `sotto sim`, с планом по резюме и вакансии). В поле ответа уже стоит
подсказка. Вакансия подставляется с ближайшего собеседования. Сессии видны в истории звонков.

## Хоткеи

В Linux регистрируются в Hyprland сами при запуске демона (через `hyprctl eval`), в конфиг ничего прописывать
не надо, он может быть read-only из home-manager; после `hyprctl reload` демон регистрирует их заново.
В Windows — глобальные сочетания через `RegisterHotKey`, тоже при запуске демона.

По умолчанию подсказки появляются **сами**: собеседник задал вопрос и замолчал, через ~0.7 с в оверлее пошёл
ответ. Хоткеи нужны редко:

| Linux | Windows | Действие |
|---|---|---|
| `SUPER+A` | `CTRL+ALT+A` | ответить сейчас (суфлёр промолчал, а подсказка нужна) |
| `SUPER+X` | `CTRL+ALT+X` | подсказка по скриншоту экрана (или «сцены», если она включена) |
| `SUPER+SHIFT+X` | `CTRL+ALT+SHIFT+X` | … по выделенной области |
| `SUPER+SHIFT+A` | `CTRL+ALT+Q` | вопросы, которые стоит задать собеседнику |
| `SUPER+H` | `CTRL+ALT+H` | спрятать / показать оверлей |

Режим «только по хоткею», ручное начало звонка и остальное — кнопки в панели. Им можно назначить клавиши
в `[hotkeys]` (`toggle_mode`, `toggle_call`, `clear`…), по умолчанию они пустые.

### Оверлей

Сверху по центру, под камерой ноутбука: читая подсказку, смотришь почти в камеру. Окно **перетаскивается мышью
за любое место**, тянется за края (или `SUPER` + левая/правая кнопка, как любое плавающее окно). Положение и размер
запоминаются. Цвета спокойные, ничего не мигает и не прыгает. Сверху тускло — состояние и имя собеседника (как только
суфлёр его услышит); посередине — подсказка, над ней тускло вопрос, на который она отвечает; придуманный опыт чуть
другим оттенком. Подсказка — не больше трёх предложений (длиннее генерация обрывается), шрифт сам уменьшается,
чтобы она влезла целиком. Внизу тускло — последние реплики разговора.

Поменять — раздел `[hotkeys]` в `config.toml` (`~/.config/sotto/config.toml` в Linux, `%APPDATA%\sotto\config.toml`
в Windows). Из терминала: `sotto ctl ask`, `sotto ctl toggle_mode`…

## Невидимость: как это устроено и что видит собеседник

* **Linux:** у окна оверлея класс `sotto-overlay` и правило Hyprland `no_screen_share`. Hyprland не отдаёт его
  содержимое ни порталу (Zoom, Meet, Телемост, Teams, Telegram, браузер), ни screencopy (OBS, grim).
* **Windows 11:** окно помечается `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`. Такие окна не попадают
  ни в «Поделиться экраном» браузера и Zoom/Meet/Teams, ни в OBS, ни в снимки экрана. Демон каждые 3 секунды
  проверяет, что правило на месте, и закрывает оверлей, если система его не приняла (например, на Windows 10
  старше 2004 — там доступно только затемнение `WDA_MONITOR`).
* **Важно:** на месте скрытого окна в трансляции **чёрный прямоугольник**. При показе всего экрана
  собеседник его увидит. Варианты:
  1. Показывать **окно**, а не экран: оверлея там нет вовсе.
  2. **Сцена** (`sotto stage on`, только Linux): создаётся виртуальный монитор `SOTTO-STAGE` справа от основного,
     а на основном на весь экран открывается его зеркало. В звонке показываешь монитор `SOTTO-STAGE`: там только
     то, что ты на него перенёс (рабочий стол `stage`). Оверлей живёт на основном мониторе поверх зеркала и в
     трансляцию не попадает даже чёрным прямоугольником. Курсор на сцену переводится движением вправо за край
     экрана. `sotto stage off` возвращает всё как было. В Windows виртуального монитора без стороннего драйвера
     не создать — используй вариант 1 или 3.
  3. Второй физический монитор: оверлей на одном, показываешь другой.

## Звук: микрофон и голос собеседника

Два независимых канала: **«я»** — микрофон, **«собеседники»** — звук системы (то, что ты слышишь
в звонке). Раздельные каналы дают бесплатную разметку: кто говорит.

* **Linux:** микрофон — источник PipeWire, собеседники — монитор выхода PipeWire.
* **Windows:** собеседники — loopback (WASAPI) **всех устройств вывода сразу**, а отдаётся то, где
  сейчас играет звук (выбор «залипает» на секунду, чтобы тишина между словами не переключала канал).
  Discord, Zoom и браузер сами выбирают, куда играть — наушники, колонки, виртуальный кабель
  (NVIDIA Broadcast и подобные), — Sotto всё равно услышит. Если указать конкретное устройство
  в `[audio].system` (панель → Настройки → Звук), слушается только оно.

Проверить, что доходит: на **главной странице панели** две полосы уровня — «я» и «собеседники».
Если говорит собеседник, а «собеседники» молчат — звук звонка играет не туда; если молчит «я» —
не тот микрофон. Оба устройства меняются в «Настройках → Звук» без перезапуска.

Наушники надёжнее колонок: микрофон не подхватывает голос собеседника (такие дубли Sotto
отбрасывает, но лишних реплик лучше не создавать).

## Провайдеры и модели — почему так

Провайдера выбираешь в панели → **Настройки → Провайдер моделей** (или `sotto setup`). Пресет сам подставляет
адрес API, имена моделей и режим распознавания речи; ключ вводится там же. Рядом кнопка **«Проверить ключ
и адрес»** — делает один короткий запрос и показывает ответ или ошибку.

| Провайдер | Подсказки | Распознавание речи | Скриншоты | Ключ |
|---|---|---|---|---|
| **OpenRouter** (по умолчанию) | да | облако или локально | да | openrouter.ai/keys |
| **DeepSeek** | да | локально (в API его нет) | нет: в DeepSeek API нет моделей со зрением | platform.deepseek.com |
| **Свой сервер** (LM Studio, vLLM, ollama, прокси) | да | локально | если у модели есть зрение — впиши её в «Модели» | обычно не нужен |

Подробности по DeepSeek: адрес `https://api.deepseek.com/v1`, модели `deepseek-chat` (для подсказок;
`deepseek-reasoner` — точнее, но думает дольше). В Sotto уходит только стандартный набор полей OpenAI —
OpenRouter-специфичные (выбор провайдера, `usage`, `reasoning`, `session_id`) отключаются автоматически,
иначе DeepSeek отвечает 400. Речь распознаётся локально тем же Whisper'ом, что и в режиме без ключа.

**OpenRouter — один ключ и один баланс** и для ответов, и для распознавания речи (`/audio/transcriptions`).
Его минус: распознавание не потоковое. Для суфлёра это не страшно: локальный детектор речи (Silero) режет звук
на реплики по паузам, каждая реплика распознаётся за доли секунды, а отвечать всё равно нужно, когда собеседник
договорил.

**Про «огромную latency» в рейтингах OpenRouter.** Там показано время до первого токена (TTFT), усреднённое
по миру и включающее «размышления» моделей. Sotto выключает размышления для подсказок (у моделей, где их нельзя выключить, ставит минимальные), выбирает провайдера по
задержке, держит неизменную часть промпта первой (её кэшируют) и звонок на одном провайдере (`session_id`).
Собственная прослойка OpenRouter добавляет десятки миллисекунд. Реальные цифры из твоей сети покажет `sotto bench`.

Роли моделей (`[models]` в конфиге; на OpenRouter подбираются `sotto bench --apply`):

| Роль | По умолчанию | Почему |
|---|---|---|
| `answer` | `openai/gpt-6.1-terra` | выбрана слепым тестом: живой интервьюер оценивал подсказки шести моделей на своём же собеседовании, у этой больше всего «лучших» и меньше всего «не принял бы». ~0.9 с до первых слов, ~$0.25 за час. Запасная `answer_fallback` (DeepSeek v4.1 flash) пишет подсказку, если основная упёрлась в лимит |
| `vision` | `anthropic/claude-sonnet-5.5` | скриншоты редкие, а слабая модель путается в интерфейсах, поэтому здесь сильная |
| `answer_short` / `answer_detailed` | haiku / sonnet | режим «короткий + подробный» |
| `utility` | haiku | имена из представлений |
| `stt` | `openai/whisper-large-v3-turbo` | облако: ~$0.01/час, но 2–4 с на фразу. При `[audio].stt = "auto"` (по умолчанию) и видеокарте NVIDIA (`nix develop .#cuda`) распознаёт локально: ~0.3 с, бесплатно |

**Сколько стоит час собеседования в авто-режиме** (~40 ответов, ~10 скриншотов): распознавание $0.01–0.2,
ответы ~$0.25, скриншоты ~$0.15. Итого **$0.4–0.6**. Для сравнения, у коммерческих аналогов сутки стоят около 1000 ₽.
Расход виден на главной панели (баланс OpenRouter) и у каждой подсказки (`usage.cost`).

Без ключа Sotto тоже работает: распознаёт локально, пишет экран и звук, ищет по звонкам, тренирует, собирает
вакансии. Без ключа нет только подсказок в реальном времени.

Если ключ есть только от DeepSeek — выбирай провайдера **DeepSeek**, вставь ключ и нажми «Проверить ключ
и адрес». Подсказки, запись, расшифровка (локальная), поиск, тренеры и вакансии работают; подсказки по
скриншоту — нет, потому что в DeepSeek API нет моделей со зрением. Хочешь и скриншоты, и один ключ —
OpenRouter; хочешь только свой сервер — пресет «Свой OpenAI-совместимый сервер».

## Тестовый интервьюер (`sotto sim`)

Синтезированный голос звучит из колонок, демон слышит его как настоящий звонок.

`sotto sim tutorial` — тренировочное собеседование. Перед началом в терминале короткая инструкция (читаешь сколько
нужно, Enter — начать). Дальше интервьюер задаёт вопрос, **ждёт, пока ты ответишь и договоришь** (паузы посреди
ответа не перебивает), коротко реагирует на сказанное и спрашивает дальше; на твои вопросы в конце отвечает. В конце —
узнал ли суфлёр имя, за сколько появлялись подсказки и ссылка на запись разговора в панели.

Вакансия: открой её на сайте, Ctrl+A, Ctrl+C и на вопрос «Вакансия или роль» введи `б` — текст возьмётся из буфера
обмена (или укажи путь к файлу). Модель сожмёт его в выжимку: интервьюер будет из этой компании и спросит по её
требованиям, а суфлёр получит выжимку как бриф. Резюме из профиля интервьюер тоже «читал» и спрашивает по нему.

Остальные сценарии — проверка суфлёра по шагам с замерами:

```bash
sotto sim --list
sotto sim tutorial     # тренировочное собеседование: интервьюер ждёт твоих ответов и реагирует на них
sotto sim backend_ru   # авто-режим, два интервьюера, имена, молчание на «понятно, спасибо»
sotto sim english      # английский и смешанный RU/EN вопрос
```

В конце — отчёт: сколько шагов пройдено, медианы «конец фразы → реплика в расшифровке → первое слово
подсказки → ответ целиком». JSON-отчёт лежит в `~/.local/state/sotto/sim/`. Свои сценарии — TOML в
`sotto/sim/scenarios/`, формат описан в `sotto/sim/simulator.py`.

## Тренеры

Панель → **Тренеры** (или `sotto trainer knowledge "индексы в PostgreSQL"`, `sotto trainer english --mode lesson`).
Тренер говорит, ты отвечаешь голосом, в панели появляется разбор каждого ответа. Скажи «стоп», чтобы закончить.

* Речь распознаётся и синтезируется **локально**, ход разговора ведёт твой CLI-агент. Пауза перед репликой
  тренера (3–10 с) — это агент думает.
* Темы подбираются сами и обновляются после каждого собеседования, отказа и нового собеседования в плане: агент
  сводит вакансии ближайших собеседований, вопросы с твоих реальных звонков, разборы отказов, требования собранных
  вакансий и типичные вопросы для роли. Слабые темы и повторяющиеся ошибки возвращаются по интервальному повторению.

## Вакансии, резюме, отклики

1. **Профиль** (панель → Профиль) — основа всего. Можно вставить заметки, агент разложит их по разделам и ничего не придумает.
2. **Источники** (панель → Вакансии):
   * Telegram: `api_id`/`api_hash` с my.telegram.org, вход `sotto jobs login-telegram`, список каналов.
   * LinkedIn: `sotto jobs login-linkedin` (отдельный профиль браузера, вход руками один раз).
   * Почта: SMTP и пароль приложения.
3. **Собрать новые** (панель → Вакансии). Агент отделяет вакансии от мусора (в том числе посты «ищем» в
   LinkedIn-ленте), достаёт контакты («пишите @…», e-mail), оценивает соответствие профилю, группирует в кластеры
   и предлагает новые поисковые запросы.
4. **Резюме** (панель → Резюме): базовое резюме собирает агент, потом резюме и шаблон письма на каждый кластер.
   Под конкретную вакансию можно поправить на её странице.
5. **Отклик** — кнопкой на странице вакансии.

**Как не получить бан и не попасть в спам**

* Telegram: читаем только твои каналы плюс до 5 глобальных поисков за сбор, соблюдаем `FloodWait`. Пишем только
  тем, кто сам дал контакт, одному человеку один раз, не больше 8 в сутки и не чаще раза в 4 минуты. Текст у
  каждого свой (должность и компания). Лучше со второго аккаунта.
* LinkedIn: чтение медленное, с паузами и суточным лимитом страниц (25). Разметку не парсим жёстко, поля
  раскладывает агент. **Отправку не автоматизируем**: страница открывается в твоём браузере, текст в буфере.
* Почта: со своего ящика, по одному письму, обычный текст и PDF, без трекинга, не больше 15 в сутки.

## Эксперимент: переводчик звонка

`sotto translate run` — двусторонний голосовой перевод. Собеседники говорят по-английски — ты слышишь по-русски,
у каждого свой голос. Ты говоришь по-русски — они слышат английский **твоим голосом** (клон по 15-секундному
образцу, `sotto translate enroll`). Задержка ~1.5–3 с от конца фразы. Подробности и ограничения —
[sotto/experimental/translator/README.md](sotto/experimental/translator/README.md).

Работает только в Linux: переводчику нужны виртуальные устройства PipeWire, которые звонок видит как
микрофон и колонки. В Windows `sotto translate` честно скажет, что эксперимент недоступен.

## Где что лежит

| Linux | Windows | |
|---|---|---|
| `~/.config/sotto/config.toml` | `%APPDATA%\sotto\config.toml` | настройки: провайдер, ключ, модели (ключ можно задать и в `OPENROUTER_API_KEY`) |
| `~/.config/sotto/profile.md` | `%APPDATA%\sotto\profile.md` | профиль |
| `~/.config/sotto/prompts/*.md` | `%APPDATA%\sotto\prompts\*.md` | твои версии промптов (перекрывают встроенные, см. «Промпты») |
| `~/.local/share/sotto/sotto.db` | `%LOCALAPPDATA%\sotto\sotto.db` | звонки, реплики, ответы, легенда, тренировки, вакансии (SQLite + sqlite-vec) |
| `~/.local/share/sotto/recordings/` | `%LOCALAPPDATA%\sotto\recordings\` | записи экрана по дням (`.mkv`: дорожки «все», «микрофон», «собеседники») |
| `~/.local/share/sotto/models/` | `%LOCALAPPDATA%\sotto\models\` | локальные модели |
| `~/.local/state/sotto/sotto.log` | `%LOCALAPPDATA%\sotto\state\sotto.log` | лог |

Всё личное — ключ, профиль (резюме), записи, звонки, легенда — лежит только в этих каталогах, в репозитории
ничего этого нет.

## Промпты

Все инструкции для моделей — Markdown-файлы в [`sotto/prompts/`](sotto/prompts): подсказки суфлёра, бриф, итоги
звонка, разбор отказов, тренировочный интервьюер, голосовые тренеры, подбор тем. Поменять любой:

* панель → **Промпты**: правишь текст или пишешь пожелание агенту («отвечай короче», «упор на Go»);
* или положи файл с тем же именем в `~/.config/sotto/prompts/` — он перекроет встроенный. Удалишь — вернётся встроенный.

Слова в фигурных скобках (`{profile}`, `{topic}`…) подставляет программа. Профиль кандидата в промпты не
вшит: он подставляется из `profile.md`, поэтому один и тот же набор промптов работает для любого человека.

## Устройство (для тех, кто будет развивать)

```
sotto/
  daemon.py          связывает всё; HTTP-API и SSE-события (/api/events)
  cli.py             команда sotto
  config.py          все настройки — dataclass'ы со значениями по умолчанию
  db.py              схема SQLite, одна на всё
  events.py          шина событий (оверлей и панель её слушают)
  openrouter.py      клиент OpenAI-совместимого API: OpenRouter, DeepSeek, свой сервер
  agents.py          мост к CLI-агентам: как запустить, как достать ответ, лимиты и откат на следующего
  desktop.py         рабочий стол: одна точка входа — окна, хоткеи, скриншоты, «сцена», буфер обмена
  hypr.py            Linux: Hyprland — правила окон, хоткеи, сцена, скриншоты, события
  winsys.py          Windows: Win32 — исключение окна из захвата, RegisterHotKey, WASAPI, реестр
  proc.py            запуск дочерних процессов (своя сессия в Linux, Job Object в Windows)
  local.py           HTTP к своей панели на 127.0.0.1 — мимо системного прокси
  shot.py            снимок экрана / выделение области (отдельный процесс)
  calls.py           звонок = чужое приложение пишет микрофон (pw-dump / ConsentStore)
  recorder.py        постоянная запись экрана и звука
  search.py          эмбеддинги (fastembed) + sqlite-vec
  postcall.py        итоги звонка агентом
  interviews.py      план собеседований, привязка звонков, напоминания, разбор отказов
  textchat.py        текстовая проверка подсказок и тренировка с интервьюером
  overlay.py         окно подсказок (Qt), отдельный процесс
  audio/             захват (pw-record / WASAPI), VAD, голосовые отпечатки, синтез, локальный Whisper
  copilot/           промпты, сборка контекста, движок подсказок, путь «звук → реплика»
  trainer/           голосовые тренеры и темы
  jobs/              источники, разбор, кластеры, резюме, отклики
  sim/               тестовый интервьюер и замер моделей
  web/               панель (FastAPI + Jinja2, без сборки фронтенда)
  experimental/      эксперименты: translator/ — голосовой переводчик звонка (только Linux)
  prompts/           встроенные промпты
```

Поток данных во время звонка:
`pw-record / WASAPI → VAD (реплика) → голосовой отпечаток (кто) → распознавание → SQLite → событие → движок подсказок → провайдер моделей (поток) → события → оверлей`.

Как расширять:
* **Новый агент:** добавь запись в `AGENTS` в `sotto/agents.py` (как запустить с промптом и как достать ответ).
* **Новый источник вакансий:** функция, возвращающая `list[RawPost]`. Дальше `jobs/extract.ingest` и кластеры сделают остальное.
* **Новый тип подсказки:** промпт в `sotto/prompts/`, метод в `copilot/engine.py`, ветка в `Daemon.action()` и хоткей в `config.Hotkeys`.

Разработка:

```bash
nix develop          # или nix develop .#cuda
python -m pytest     # тесты без звука, окон и сети
python -m sotto run --no-overlay --no-desktop   # демон без окон и хоткеев
```

Windows: `python -m venv .venv; .venv\Scripts\pip install -e .` — и те же команды
(`.venv\Scripts\python -m pytest`, `.venv\Scripts\sotto run --no-desktop`).

## Честно об ограничениях

* Невидимость гарантирует система, а не Sotto: в Hyprland это правило `no_screen_share` (проверено на 0.57),
  в Windows — `WDA_EXCLUDEFROMCAPTURE` (нужна сборка 19041+, то есть Windows 10 2004 или новее; на Windows 11
  всегда). Чёрный прямоугольник при показе всего экрана — см. раздел «Невидимость».
* Windows: виртуального монитора «сцена» нет (нужен драйвер дисплея), а часть сочетаний с `SUPER` занята
  самой системой — поэтому хоткеи там на `CTRL + ALT`.
* Используешь колонки, а не наушники — микрофон слышит собеседника. Sotto отбрасывает такие дубли, но в наушниках надёжнее.
  В Windows системный звук берётся loopback'ом выхода, так что «собеседники» = всё, что играет в колонках/наушниках.
* Распознавание имён и людей по голосу ошибается на очень коротких репликах. Исправляется в карточке звонка.
* LinkedIn меняет вёрстку. Извлечение сделано максимально устойчивым, но может потребовать правки `jobs/linkedin.py`.
* Использование суфлёра на собеседовании может нарушать правила работодателя — это твоя ответственность.
